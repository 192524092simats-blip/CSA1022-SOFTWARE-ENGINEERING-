PROBLEM STATEMENT
Demonstrate how to work collaboratively in Git/GitHub on a project using the fork-and-pull
request workflow.
Tasks:
● Fork an existing public GitHub repository (e.g., a sample JavaScript or Python project).
● Clone the forked repository to your local machine using Git.
● Create a new branch for the feature or change you want to work on.
● Make modifications or add new features (e.g., add a function, fix a bug, or update the
   README).
● Commit your changes and push the branch to GitHub.
● Go to the GitHub repository and create a pull request to merge your feature branch into the
   main branch.
● Review the pull request and provide feedback on the changes.
● Respond to feedback by making additional commits to the

AIM
To collaborate on a GitHub project using the fork-and-pull-request workflow: fork a public
repository, clone it, create a branch, make changes, push them and raise a pull request for review
and merge.

SOFTWARE REQUIREMENTS
● Git (Git Bash)
● GitHub account
● Visual Studio Code

PROCEDURE
Step 1: Fork the Repository
● Open the GitHub website and sign in to your account.
● Navigate to an existing public repository.
● Click the Fork button to create a copy of the repository under your GitHub account.
Step 2: Clone the Forked Repository
● Copy the URL of the forked repository.
● Open Git Bash or the terminal.
● Use the git clone command to clone the repository to your local machine.
● Navigate to the project directory using the cd command.
 git clone https://github.com/<your-username>/first-contributions.git
 cd first-contributions
Step 3: Create a New Branch
● Create a new branch using the git checkout -b command.
● Verify that the new branch has been created successfully.
● Switch to the newly created branch before making any changes.
 git checkout -b update-readme
 git branch
Step 4: Modify the Project
● Open the project in a code editor such as Visual Studio Code.
● Make the required changes, such as adding a new feature, fixing a bug, or updating the
   README file.
● Save all the modified files.
Step 5: Commit and Push the Changes
● Check the modified files using the git status command.
● Stage the changes using the git add command.
● Commit the changes with an appropriate commit message using the git commit command.
● Push the feature branch to the forked GitHub repository using the git push command.
 git status
 git add README.md
 git commit -m "Updated README for collaboration experiment"
 git push -u origin update-readme
Step 6: Create a Pull Request
● Open the forked repository on GitHub.
● Click Compare & Pull Request or New Pull Request.
● Select the feature branch as the source and the main branch as the destination.
● Add a suitable title and description.
● Submit the pull request.
Step 7: Review the Pull Request
● Review the changes shown in the pull request.
● Verify the modified files and commit history.
● Add review comments or feedback if required.
Step 8: Update the Pull Request
● Make additional modifications if feedback is received.
● Commit the updated changes.
● Push the latest commits to the same feature branch.
● Verify that the pull request is updated automatically.
 git add .
 git commit -m "Addressed review comments"
 git push
Step 9: Merge the Pull Request
● After the pull request is approved, merge it into the main branch.
● Confirm that the changes have been successfully merged.
● Delete the feature branch if it is no longer required.
Note: GitHub shows “You cannot merge this Pull Request because it targets the original
repository (firstcontributions/first-contributions)”. Only the maintainers of the original
repository can merge it.
Step 10: Document the Work
● Copy the pull request URL.
● Prepare a brief summary of the changes made.
● Submit the pull request link along with the summary for evaluation.
● https://github.com/firstcontributions/first-contributions/pull/122481

----- fork_pr_demo.sh -----
#!/usr/bin/env bash
# Experiment 14 - fork-and-pull-request workflow
# Runs the whole workflow on your machine. A local bare repository (origin.git) plays the role of GitHub,
# so no account or internet is needed. For the REAL GitHub steps follow the Procedure in Experiment_Details.txt.
set -e
W=$(mktemp -d); cd "$W"
export GIT_AUTHOR_NAME="Student" GIT_AUTHOR_EMAIL="student@example.com" GIT_COMMITTER_NAME="Student" GIT_COMMITTER_EMAIL="student@example.com"
export GIT_MERGE_AUTOEDIT=no GIT_EDITOR=true
git config --global init.defaultBranch main 2>/dev/null || true
git init -q --bare -b main origin.git
git clone -q origin.git seed 2>/dev/null; cd seed; git checkout -q -b main 2>/dev/null || true
printf '# My-Personal-Project\n\nInitial README created on GitHub.\n' > README.md
git add README.md; git commit -q -m "Initial commit"; git push -q origin main; cd ..; rm -rf seed
show() { echo; local s="\$"; for a in "$@"; do case "$a" in *\ *) s="$s '$a'";; *) s="$s $a";; esac; done; echo "$s"; "$@" 2>&1; }

# "fork" = a second bare repository cloned from the upstream repository
git clone -q --bare origin.git fork.git
show git clone fork.git first-contributions
cd first-contributions
show git checkout -b update-readme
show git branch
echo "Added my name to the contributors list" >> README.md
show git status --short
show git add README.md
show git commit -m "Updated README for collaboration experiment"
show git push -u origin update-readme
echo "Reviewer: please add one more line about the workflow." # review comment (done on GitHub in the real experiment)
echo "Workflow: fork -> clone -> branch -> commit -> push -> pull request" >> README.md
show git add .
show git commit -m "Addressed review comments"
show git push
cd ..
# maintainer side: merging the pull request into upstream main
git clone -q origin.git maintainer; cd maintainer
git fetch -q ../fork.git update-readme
show git merge --no-ff FETCH_HEAD -m "Merge pull request: update-readme"
show git log --oneline --graph

echo; echo "Workspace: $W"

● Pull Request link: https://github.com/firstcontributions/first-contributions/pull/122481
