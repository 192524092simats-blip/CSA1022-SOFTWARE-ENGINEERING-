EXPERIMENT NUMBER : 27
EXPERIMENT TITLE  : COMMITTING AND PUSHING CHANGES TO GITHUB
TOOLS USED        : Git/GitHub      COURSE OUTCOME: CO4

PROBLEM STATEMENT
After modifying a file in a cloned repository, commit the changes locally and push them to
GitHub.
Tasks:
● Clone a repository (from question 1).
● Modify a file (e.g., README.md).
● Stage the changes with git add.
● Commit the changes with git commit -m "Updated README".
● Push the changes to GitHub using git push.

AIM
To modify a file in a cloned repository, stage and commit the changes with a meaningful
message, and push them to the remote GitHub repository.

SOFTWARE REQUIREMENTS
● Git (Git Bash)
● GitHub
● Visual Studio Code

PROCEDURE
Step 1: Clone the Repository
● Open Git Bash on the local machine.
● Navigate to the location where the repository needs to be stored.
● Clone the GitHub repository using the git clone command.
● Wait for the cloning process to complete successfully.
 git clone <repository_url>
Step 2: Navigate to the Repository
● Move into the cloned repository directory using the cd command.
● List the repository files to verify that the repository was cloned successfully.
 cd <repository_name>
 ls
Step 3: Open the Repository and Modify the File
● Open the cloned repository in Visual Studio Code or any preferred code editor.
● Locate the file that needs to be modified, such as README.md or any source code file.
 code .
● Open the selected file.
● Make a small modification, such as updating a line of text, correcting a spelling mistake, or
   adding a short description.
● Save the modified file.
Step 4: Check the Repository Status
● Return to Git Bash.
● Check the status of the repository to identify the modified file.
 git status
● Verify that README.md is displayed as a modified file.
Step 5: Stage the Changes
● Add the modified file to the staging area using git add.
● Verify that the file has been staged successfully.
 git add README.md
 git status
Step 6: Commit the Changes
● Commit the staged changes to the local Git repository.
● Provide a meaningful commit message describing the modification.
 git commit -m "Updated README"
Step 7: Push the Changes to GitHub
● Upload the committed changes from the local repository to the GitHub remote repository
   using git push.
 git push origin main
● Wait for the push operation to complete successfully.
Step 8: Verify the Changes
● Open the GitHub repository in a web browser.
● Refresh the repository page.
● Open README.md and verify that the updated content is displayed.
● Check the commit history to confirm that the new commit has been added successfully.

SOURCE CODE (files in Source_Code/)

----- commit_and_push_demo.sh -----
#!/usr/bin/env bash
# Experiment 27 - commit and push changes
# Runs the whole workflow on your machine. A local bare repository (origin.git) plays the role of GitHub,
# so no account or internet is needed. For the REAL GitHub steps follow the Procedure in Experiment_Details.txt.
set -e
W=$(mktemp -d); cd "$W"
export GIT_AUTHOR_NAME="Student" GIT_AUTHOR_EMAIL="student@example.com" GIT_COMMITTER_NAME="Student" GIT_COMMITTER_EMAIL="student@example.com"
export GIT_MERGE_AUTOEDIT=no GIT_EDITOR=true
git config --global init.defaultBranch main 2>/dev/null || true
git init -q --bare -b main origin.git
git clone -q origin.git seed 2>/dev/null; cd seed; git checkout -q -b main 2>/dev/null || true
printf '# My-Personal-Project\n\nInitial README created on GitHub.\n' > README.md
git add README.md; git commit -q -m "Initial commit"; git push -q origin main; cd ..; rm -rf seed
show() { echo; local s="\$"; for a in "$@"; do case "$a" in *\ *) s="$s '$a'";; *) s="$s $a";; esac; done; echo "$s"; "$@" 2>&1; }

git clone -q origin.git My-Personal-Project; cd My-Personal-Project
show ls
echo "Updated line added for Experiment 27." >> README.md
show git status
show git add README.md
show git commit -m "Updated README"
show git status
show git push origin main
show git status
show git log --oneline

echo; echo "Workspace: $W"


EXPECTED OUTPUT
● git commit -m "Updated README" shows 1 file changed.
● git status shows the branch ahead of origin/main by 1 commit; after git push it is up to date.
● The updated README is visible on GitHub with the new commit message.
